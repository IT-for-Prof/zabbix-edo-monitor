# EDO Monitor

> Шаблон Zabbix 7.0 и PowerShell-проба: доступность Контур.Диадок/Экстерн, Госуслуг, ФНС (включая ГОСТ-кабинеты), Такскома и Честного знака **с рабочего места пользователя** и с названием класса отказа.

**Автор:** Konstantin Tyutyunnik / Константин Тютюнник · [itforprof.com](https://itforprof.com)

## Зачем

Пользователи ЭДО на терминальных серверах теряют доступ к Диадоку, Экстерну, кабинетам ФНС и Такскому по разным причинам: сервис лежит, провайдерский ТСПУ режет соединение, антивирус подменяет TLS, на сервере нет КриптоПро, адрес не покрыт правилом брандмауэра. Страница `help.kontur.ru/check` диагностирует это только вручную, из браузера и с расширением. Этот шаблон проверяет то же самое постоянно, с самого Windows-сервера, прямым путём, без Python и без прокси, и говорит, **на каком шаге** соединение ломается.

## Что проверяется

Для каждой цели проба `edo.ps1` проходит цепочку DNS → TCP → TLS → HTTP и останавливается на первом отказе. Список целей задаётся макросами Zabbix, скрипт на серверах не содержит ни одного адреса.

| Режим | Что делает |
|---|---|
| `http` | `GET` по пути цели, читает строку статуса. Любой ответ ниже 500 — сервис доступен. На порту 80 — без TLS |
| `stall` | `POST` 256 КБ порциями по 4 КБ. Обрыв после отправки части тела — класс 50 |
| `gost` | TCP до цели, затем `csptest -tlsc -hello -exchange 3`: сервер должен принять ClientHello только с ГОСТ-обменом. Полное рукопожатие без ключа пользователя невозможно — кабинеты требуют клиентский сертификат |

Цели по умолчанию:

| Макрос | Цели |
|---|---|
| `{$EDO.TARGETS.KONTUR}` | auth, api, identity, update, pki.skbkontur.ru, ca, diadoc, diadoc-api, edi, edi-api, extern, cdn.kontur.host, m4d — сверено с профилями diadoc, ke и m4d страницы `help.kontur.ru/check` |
| `{$EDO.TARGETS.STALL}` | `help.kontur.ru/check/post` — тот же приёмник, что у страницы проверки Контура |
| `{$EDO.TARGETS.GOSUSLUGI}` | www.gosuslugi.ru, esia.gosuslugi.ru |
| `{$EDO.TARGETS.FNS}` | www.nalog.gov.ru, lkul.nalog.ru, lkip2.nalog.ru |
| `{$EDO.TARGETS.FNS.GOST}` | lkulgost.nalog.ru, lkipgost.nalog.ru |
| `{$EDO.TARGETS.TAXCOM}` | online.taxcom.ru, lk-new.taxcom.ru |
| `{$EDO.TARGETS.CRPT}` | markirovka.crpt.ru, ismp.crpt.ru, suzgrid.crpt.ru, crpt.ru |
| `{$EDO.TARGETS.EXTRA}` | пусто — добавки офиса или хоста |

## На что реагирует

На каждую цель обнаружение создаёт элемент «ответ пробы» (JSON), три зависимых элемента и шесть триггеров. На хост — четыре вычисляемых сводки по целям и три триггера.

| Триггер | Серьёзность | Поднимается | Закрывается |
|---|---|---|---|
| `EDO: проба не работает на хосте` | Average, один на хост | ни одна цель не прислала класс за `{$EDO.NODATA.HOST}` или у `{$EDO.MASS.PCT}`% целей класс 90–91 | условие ушло |
| `EDO: массовый отказ с хоста` | High, один на хост | последняя проверка с классом 10–50 у `{$EDO.MASS.PCT}`% целей, не меньше `{$EDO.MASS.MIN}` | условие ушло |
| `EDO: версия скрипта пробы не совпадает` | Average, один на хост | MD5 `edo.ps1` на хосте ≠ `{$EDO.SCRIPT.MD5}` | MD5 совпал |
| `EDO <цель>: недоступен несколько проверок подряд` | High | все проверки за `{$EDO.FAIL.PERIOD}` (по умолчанию `#3`) с классом 10–50 | **только успешной проверкой** (класс 0) |
| `EDO <цель>: нет данных пробы` | Average | нет класса дольше `{$EDO.NODATA}` | пришли данные |
| `EDO <цель>: проверка невозможна` | Average | две проверки подряд с классом 90–91 | класс ниже 90 |
| `EDO <цель>: нестабилен` | Warning, только дашборд | класс сменился `{$EDO.UNSTABLE.CHANGES}` раз за `{$EDO.UNSTABLE.PERIOD}`, и среди последних `{$EDO.FAIL.PERIOD}` есть успешная | условие ушло |
| `EDO <цель>: медленный ответ` | Warning, только дашборд | все успешные проверки за `{$EDO.FAIL.PERIOD}` дольше `{$EDO.SLOW.MS}` | **только быстрой успешной проверкой** |
| `EDO <цель>: сертификат сервера истекает` | Warning, только дашборд | до конца сертификата меньше `{$EDO.CERT.DAYS}` дней | **только новым сертификатом**; -1 (отказ до TLS) не закрывает |

Зависимости — цепочка, Zabbix проходит её насквозь:

```
Windows: Active checks are not available, Windows: Zabbix agent is not available
├── EDO: версия скрипта пробы не совпадает
└── EDO: проба не работает на хосте
    ├── EDO <цель>: нет данных пробы
    ├── EDO <цель>: проверка невозможна
    └── EDO: массовый отказ с хоста

EDO <цель>: недоступен          → массовый отказ с хоста, нет данных пробы, проверка невозможна
EDO <цель>: нестабилен,
  медленный ответ, сертификат   → нет данных пробы, проверка невозможна
```

Когда молчит агент, проба или сеть всего хоста, приходит одна проблема хоста, а не по одной на цель. Хостовые триггеры поднимаются раньше триггеров целей: сводки считаются раз в минуту по последнему значению каждой цели, а цели ждут `{$EDO.FAIL.PERIOD}` отказов подряд или `{$EDO.NODATA}` тишины. После закрытия хостового триггера цель, которая всё ещё не работает, поднимет свой на следующей проверке: зависимый триггер пересчитывается только на новом значении.

«Недоступен» и «нестабилен» не бывают одновременно: первому нужны отказы подряд, второму — успешная проверка среди тех же последних. Одиночный сбой (две смены класса) и сплошной отказ с восстановлением (тоже две) «нестабилен» не поднимают; две отдельные вспышки за час — поднимают. Так видна балансировка, отдающая время от времени адрес, не покрытый правилом брандмауэра.

У каждого прототипа триггера есть ссылка «Последние данные цели» — фильтр по тегу `endpoint`.

Теги: на шаблоне `class: service`, `target: edo`, `vendor: itforprof`; на элементах `component` (`summary` у сводок хоста); на элементах целей — `endpoint` (host цели), `mode`, `service` (имя цели); на триггерах `scope` (`availability`, `data-collection`, `performance`, `tls`, `configuration`), на триггерах целей ещё `endpoint` и `service`. По ним фильтруются проблемы, условия действий и обслуживание на время работ у одного сервиса.

## Требования

- Windows Server 2019, 2022 или 2025; встроенный Windows PowerShell 5.1.
- Zabbix agent 2 версии 7.0 и новее, активные проверки.
- Шаблон «Windows by Zabbix agent active» привязан к тому же хосту: от его триггеров доступности агента зависят триггеры этого шаблона, без него импорт зависимостей не пройдёт.
- КриптоПро CSP — только для ГОСТ-целей (проверено на 5.0.12000 и 5.0.13000).
- Исходящий TCP 80/443 к целям для `powershell.exe`. На хостах, где исходящий трафик по умолчанию запрещён, нужны разрешающие правила для адресов целей.

## Установка

На каждом наблюдаемом хосте, от администратора:

```powershell
$agent = 'C:\Program Files\Zabbix Agent 2'
$scripts = Join-Path $agent 'scripts'
New-Item -ItemType Directory -Force $scripts | Out-Null
# Запись — только Administrators и SYSTEM: скрипт исполняется от LocalSystem.
icacls $scripts /inheritance:r /grant:r '*S-1-5-32-544:(OI)(CI)F' '*S-1-5-18:(OI)(CI)F' '*S-1-5-32-545:(OI)(CI)RX'
Copy-Item .\agent\edo.ps1 (Join-Path $scripts 'edo.ps1')
Copy-Item .\agent\edo-monitor.conf (Join-Path $agent 'zabbix_agent2.d\edo-monitor.conf')
Restart-Service 'Zabbix Agent 2'
```

Скрипт лежит по пути `C:\Program Files\Zabbix Agent 2\scripts\edo.ps1` — этот же путь записан в `edo-monitor.conf` и в элементе `vfs.file.md5sum` шаблона. Файлы берутся из git-клона с CRLF (так их кладёт `.gitattributes`), иначе MD5 не совпадёт с `{$EDO.SCRIPT.MD5}`.

Проверка на хосте до привязки шаблона:

```powershell
& 'C:\Program Files\Zabbix Agent 2\zabbix_agent2.exe' -c 'C:\Program Files\Zabbix Agent 2\zabbix_agent2.conf' -t 'edo.probe[http,diadoc.kontur.ru,443,/_status/ping]'
```

В Zabbix:

1. Импортировать `template/edo-monitor-by-zabbix-agent-active.yaml`: «Create new» и «Update existing» включены, «Delete missing» выключен.
2. Привязать шаблон к хосту вместе с «Windows by Zabbix agent active».
3. Обнаружение запустится в течение часа: «Execute now» для активных элементов Zabbix не разрешает (`Cannot send request: wrong item type`). Чтобы не ждать: временно поставить элементу `EDO: такт обнаружения целей` на шаблоне интервал `1m`, для хостов за прокси — «Refresh configuration» прокси (API `task.create`, `type: 2`), перезапустить агент; первые данные проб ускоряет временный макрос хоста `{$EDO.INTERVAL}` = `1m`. После первого обнаружения всё вернуть.

Новая версия скрипта: раскатать `edo.ps1`, затем записать его MD5 в `{$EDO.SCRIPT.MD5}` на шаблоне (`(Get-FileHash edo.ps1 -Algorithm MD5).Hash.ToLower()`). Отстающие хосты покажет триггер версии.

## Управление целями

| Задача | Действие в Zabbix |
|---|---|
| Сервис сменил адрес | правка макроса группы на шаблоне; обнаружение подхватит в течение часа (за прокси — плюс ~5 минут на доставку конфигурации) |
| Цель нужна одному офису | `{$EDO.TARGETS.EXTRA}` на группе хостов офиса |
| На сервере нет КриптоПро | `{$EDO.TARGETS.FNS.GOST}` пусто на хосте; ГОСТ-проверки отключаются сразу, удаляются через 7 дней |
| С хоста нет маршрута до кабинетов ФНС | на хосте `{$EDO.TARGETS.FNS}` = `ФНС\|http\|www.nalog.gov.ru\|443\|/` и пустой `{$EDO.TARGETS.FNS.GOST}` |
| Свой порог для одной цели | макрос с контекстом, например `{$EDO.SLOW.MS:"help.kontur.ru"}` |
| Выпущена новая версия скрипта | раскатка `edo.ps1`, затем новое `{$EDO.SCRIPT.MD5}` |

Запись цели — `Имя|mode|host|port|path`, записи разделяются `;`. Ограничения:

- `mode` — `http`, `stall` или `gost`; `host` — DNS-имя или IPv4; `port` — 1–65535; `path` начинается с `/` и содержит только `A-Z a-z 0-9 . _ / -`: `~` agent2 в параметрах ключа не пропускает, а `%` пропускает, но cmd.exe раскрывает `%VAR%` до запуска пробы (проверено); регистр `mode` важен. Имя цели длиннее 100 символов обрезается — имя элемента в Zabbix ограничено 255.
- Без `?`, `&` и других символов, которые agent2 не пропускает в параметры ключа; без `'`, `\` и обратной кавычки: обратная кавычка разделяет группы целей в шаге «Регулярное выражение», а `\N` этот шаг читает как ссылку на группу.
- Неверная запись не пропадает молча: обнаружение превращает её в цель «Неверная запись: …», проба отвечает классом 91, на второй проверке поднимается Average «проверка невозможна».

## Классы отказов и что делать

Коды ниже 90 — сетевой или сервисный отказ (High по цели или «массовый отказ» по хосту), 90 и выше — проверка на этом хосте невозможна (Average). Подробности конкретного отказа — поле `error` в истории элемента «ответ пробы».

| Код | Имя | Что значит | Что делать |
|---|---|---|---|
| 0 | OK | сервис ответил (любой HTTP ниже 500; для gost — ГОСТ ClientHello принят) | — |
| 10 | DNS_FAIL | имя не разрешилось в IPv4 за 2 с | проверить DNS хоста; имя цели могло смениться |
| 20 | TCP_TIMEOUT | TCP-соединение не установилось за 5 с | сервис лежит, нет маршрута или соединение режут; сравнить с другими хостами |
| 22 | TCP_REFUSED | соединение отвергнуто (на Windows так приходит и RST на SYN) | сервис не слушает порт или соединение сбрасывают |
| 23 | TCP_FAIL | прочая ошибка сокета: AccessDenied, сеть недоступна | AccessDenied — локальный брандмауэр: адрес не покрыт разрешающим правилом |
| 30 | TLS_TIMEOUT | сервер молчит после ClientHello (или csptest не завершился) | подпись блокировки по SNI; проверить массовость |
| 31 | TLS_RESET | соединение сброшено во время TLS | типичная подпись ТСПУ |
| 32 | TLS_FAIL | рукопожатие не состоялось; для gost — сервер не принял ГОСТ ClientHello | смотреть `error`; для gost — версию КриптоПро и ErrorCode |
| 33 | CERT_UNTRUSTED | цепочка сертификата не доверена | нет корня НУЦ Минцифры на хосте или подмена TLS |
| 40 | HTTP_BAD | сервис ответил 5xx или не прислал строку статуса | сбой на стороне сервиса |
| 42 | HTTP_TIMEOUT | после запроса сервис молчит 9 с | сервис перегружен или ответ режут |
| 50 | STALL | обрыв после отправки части большого тела | подпись DPI; `bytes_sent` в истории показывает, где оборвалось |
| 90 | GOST_NO_CSP | на хосте нет `csptest.exe` КриптоПро CSP | поставить КриптоПро или очистить `{$EDO.TARGETS.FNS.GOST}` на хосте |
| 91 | PROBE_ERROR | неверные аргументы или внутренняя ошибка пробы | запись «Неверная запись: …» — исправить макрос; иначе — `error` |

## Границы

- Проверяется только прямой путь с хоста; HTTP-прокси, Zabbix proxy и эталонная точка измерения не используются.
- Подмена TLS с корнем, доверенным на машине (типичный антивирус), не обнаруживается: рукопожатие успешно. Издатель сертификата пишется в `cert_issuer` для ручного разбора.
- Вход по сертификату пользователя не проверяется: ГОСТ-проверка доходит до принятия ClientHello.
- Одна точка измерения не отличает «сервис лежит» от «режут» для 20 и 22 — это видно по массовости на разных хостах. Подписи блокировки — 30, 31, 50.

## Подводные камни

- **stderr ломает всё.** agent2 склеивает stderr скрипта со stdout в значение элемента. Проба никогда ничего не пишет в stderr; любая правка `edo.ps1` проверяется тестом формы вывода.
- **`UnsafeUserParameters` не включать.** Неверные записи обнаружение превращает в безопасную цель `invalid`; включение открыло бы передачу произвольных символов в `powershell.exe`.
- **Проба видит путь программ, а не браузера.** Если исходящий трафик по умолчанию запрещён, а браузерам разрешено всё, проба подчиняется правилам по адресам. Класс 23 при открывающемся в браузере сервисе — дыра в правиле, а не ложная тревога.
- **Маршрут определяет результат.** С хоста вне российского маршрута кабинеты ФНС дают 20; Госуслуги через российский маршрут отдают цепочку НУЦ Минцифры, и хост без этого корня получит 33.
- **Запуск PowerShell на нагруженном терминальном сервере стоит до ~3 с.** Сама проба укладывается в 25 с, таймаут элемента — 30 с.
- **Период отказов — макрос целиком.** Zabbix 7.0 не принимает `#{$MACRO}` в параметре функции (импорт падает с «incorrect expression»), поэтому `{$EDO.FAIL.PERIOD}` хранит значение вместе с решёткой: `#3`.
- **Ни одного макроса внутри JavaScript.** Zabbix до 7.0.9 и 7.2.3 (сервер и прокси) кеширует скомпилированный скрипт предобработки вместе с подставленными макросами и сбрасывает кеш только при ошибке элемента или правке шагов предобработки ([ZBX-25568](https://support.zabbix.com/browse/ZBX-25568)). С макросами в JavaScript правки `{$EDO.TARGETS.*}` на таких версиях не доходили бы до обнаружения, поэтому макросы целей подаёт шаг «Регулярное выражение», а JavaScript разбирает значение. Дефект затрагивает любой шаблон с макросами в JavaScript: сервер и прокси лучше держать не ниже 7.0.9.
- **Все макросы целей пусты — обнаружение не выключает цели.** JavaScript обнаружения в этом случае бросает ошибку: правило становится «не поддерживается», а найденные раньше цели продолжают работать. Пустой список выключил бы их все сразу и удалил через 7 дней.
- **Бюджет HTTP и большого POST — на всю фазу, а не на каждый вызов.** Иначе сервер, отдающий ответ по байту, или задушенная выгрузка растягивали бы проверку дольше таймаута элемента, и вместо класса 42/50 пришло бы «нет данных». Большой POST идёт по TLS 1.2: сессионные билеты TLS 1.3 после рукопожатия выглядели бы как ранний ответ сервера.
- **Бюджет TLS — на каждое чтение, а не на всё рукопожатие.** Узел, отдающий рукопожатие по байту, может растянуть проверку за таймаут элемента: вместо класса 30 придёт «нет данных». Асинхронное рукопожатие с общим бюджетом не годится: проверка сертификата (скриптблок PowerShell) в пуле потоков падает без runspace.
- **Первый отказ новой цели сразу даёт High.** Пока у цели меньше значений, чем в `{$EDO.FAIL.PERIOD}`, `min`/`max` считают по тем, что есть. Для работающих целей это не проявляется; новую заведомо недоступную цель лучше добавлять в `{$EDO.TARGETS.EXTRA}` на хосте в обслуживании.
- **Сводки хоста: одна `*` — один параметр ключа.** `edo.class[*]` не находит ни одной цели, нужно `edo.class[*,*,*,*]`. `last_foreach` пропускает неподдерживаемые элементы, поэтому число целей считается через `exists_foreach`: иначе при пропаже `edo-monitor.conf` оно падает до 0 и выключает «проба не работает на хосте», а nodata по целям срабатывает и на неподдерживаемых элементах.
- **Переименованный конфиг агент всё равно читает.** Если `Include` в `zabbix_agent2.conf` указывает на каталог без маски (`Include=...\zabbix_agent2.d\`), `edo-monitor.conf.off` подключается так же, как `edo-monitor.conf`. Чтобы выключить пробу, файл выносят из каталога.
- **Остановка службы агента не значит остановку мониторинга.** Если у службы «Zabbix Agent 2» заданы действия восстановления (перезапуск), `Stop-Service` считается аварийным завершением, и служба поднимается сама.
- **`csptest -silent` нет в CSP 5.0.12000** — любая команда с ним даёт `ErrorCode 0x000000a0`. Проба его не использует.

## Разработка

Тесты — Pester 6.2.0 и `powershell-yaml` 0.4.12, под Windows PowerShell 5.1:

```powershell
powershell.exe -NoProfile -Command "Invoke-Pester -Path tests -CI"
```

- `tests/Probe.Tests.ps1` — классы и контракт вывода пробы на локальных фейковых серверах.
- `tests/Template.Tests.ps1` — согласованность шаблона, пробы, конфига агента и этого README; JavaScript обнаружения исполняется через JScript.NET.
